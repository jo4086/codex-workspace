# README Roles

## Project Entry Point

A project-root `README.md` introduces the project's purpose, important capabilities or components, and useful next steps. Include installation, running, or development instructions when the project needs them and the root README is their clearest home. Give brief descriptions and links for important lower areas rather than copying their details.

## Area Entry Points

A subdirectory README explains that area's purpose, components, and local usage. It can link to documents it owns directly and to useful child-area entry points. Avoid repeating the parent README.

A `docs/README.md` can introduce the documentation area and index its directly owned documents. A category README such as `docs/foundations/README.md` explains its category and indexes member documents. Describe each linked target's role; add reading conditions or order when they help readers choose.

These are roles, not mandatory files. Choose README locations using [Navigation and Links](./navigation.md). Follow a specialized Skill's required README and reference-index structure when one applies; `my-skill-creator` owns those requirements for managed Skills.
